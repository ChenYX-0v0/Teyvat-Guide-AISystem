# 06 · 阿里云部署方案

> **定位**：本文是 `04-部署运维接入说明.md`（通用 Runbook）在**阿里云**上的落地细化。
> 通用步骤（环境变量、验收清单、故障排查）仍以 04 为准，本文只写阿里云特有的选型、网络、成本与坑。
> **目标环境**：阿里云 ECS + Docker，北京地域，AI 服务与主服务同机。

---

## 1. 组件选型映射

| 需求 | 阿里云产品 | 说明 |
| --- | --- | --- |
| 计算 | **ECS** | 与主服务**同机**（见 §4），不单独开机器 |
| 容器运行时 | Docker + Compose | 与 `docker-compose.yml` 一致 |
| 镜像仓库 | **ACR（容器镜像服务）个人版** | 免费；ECS 上 `docker login` 后 pull |
| 模型（对话） | **DeepSeek 官方 API**（公网） | 保持现状，走 `api.deepseek.com` |
| 模型（Embedding） | **百炼 `qwen3.7-text-embedding-flash`** | OpenAI 兼容，见 §3 |
| 日志 | **SLS（日志服务）** | 采集容器 stdout JSON，可直接查询/告警 |
| 监控告警 | 云监控 CMS + SLS 告警 | 见 §7 |
| 密钥（起步） | `.env` 文件（chmod 600） | 见 §8 |
| 密钥（进阶） | **KMS 凭据管家** | 规模上来后再换 |

## 2. 网络方案（最容易踩坑的部分）

### 2.1 出网：AI 服务必须能访问两个外部 API

```
ECS ──► api.deepseek.com        (HTTPS 443)  对话模型
    ──► 百炼 Embedding 端点      (HTTPS 443)  向量化（P2 才需要）
```

**如果 ECS 没有公网出口，这两个都调不通，服务会返回 502/504。** 三种做法：

| 方案 | 月成本 | 适用 | 评价 |
| --- | --- | --- | --- |
| **A. ECS 直接带固定公网带宽**（如 1~5 Mbps） | 很低（几十元量级） | **单台 ECS** | ✅ **推荐**。配合严格入方向安全组，风险可控 |
| B. 无公网 IP + 公网 NAT 网关 | **NAT 网关有独立实例费，通常数百元/月** + 流量费 | 多台 ECS 共享出口 | ⚠️ 单机场景**不划算**，成本可能超过 ECS 本身 |
| C. 无公网 IP + EIP | EIP 保有费 + 流量/带宽费 | 需要固定公网 IP | 可行，但不如 A 简单 |

> 结论：**单台 ECS 就选方案 A**。不要为了"更安全"上 NAT 网关 —— 对单机来说它的月费往往比 ECS 还贵，而安全收益可以用安全组拿到。
> 具体价格以[阿里云价格计算器](https://www.aliyun.com/price)实时值为准，本文只给量级判断。

### 2.2 入方向安全组（越少越好）

主服务与 AI 服务**同机**时，8090 压根不需要对任何人开放：

| 优先级 | 方向 | 协议/端口 | 授权对象 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | 入 | TCP 22 | **你的固定办公 IP/32** | SSH；不要用 `0.0.0.0/0` |
| 2 | 入 | TCP 8080（可选） | 你的 IP / SLB 网段 | 主服务对外端口，按主服务既有策略 |
| — | 入 | ~~TCP 8090~~ | **不要配置** | 同机走 `127.0.0.1`，无需放行 |
| — | 入 | ~~TCP 80/443~~ | 不需要 | AI 服务不对外，无需域名/证书/SLB |

> 若主服务在**另一台** ECS：加一条 `允许 源=<主服务ECS内网IP>/32 → 目的 8090`，**只放这一条**。
> 跨机时把 `AI_SERVER_HOST` 设为该 ECS 的**内网 IP**，并在 `docker-compose.yml` 把端口映射改成 `内网IP:8090:8090`。

### 2.3 出方向安全组（有个必须知道的限制）

- 安全组**出方向默认允许全部**。保持默认即可让 ECS 正常访问 DeepSeek/百炼。
- 若按安全最佳实践收紧为「默认拒绝 + 白名单放行」，**必须放行云服务内网网段**，否则云助手、云监控会失联：

```
100.100.0.0/16   → 80,443     # 云助手 / 云安全中心 / 云监控
```

- ⚠️ **安全组出方向无法按域名放行**（只能按 IP 段）。想要"只允许访问 `api.deepseek.com`"这种域名级管控，需要 **云防火墙 / NAT 防火墙**（额外付费）。结论：单机场景保持出方向默认允许，靠密钥最小权限 + 及时更新来防护。

### 2.4 内网调用（P2/P3 需要时）

若将来把 `PROMPT_STORE_MODE` 切为 `http`、或 P3 让 AI 服务回调主服务：
- 同机：`http://127.0.0.1:8080`
- 跨机：`http://<主服务内网IP>:8080`，并确认两者在**同一 VPC**
- Docker 容器内访问宿主机服务：`http://host.docker.internal:8080`（`docker-compose.yml` 已配 `extra_hosts`）

## 3. Embedding 方案（百炼）

### 3.1 选型：`qwen3.7-text-embedding-flash`

| 模型 | 可选维度 | 单价（每千输入 token） | 免费额度 |
| --- | --- | --- | --- |
| **qwen3.7-text-embedding-flash** | 1024（默认）/ 768 / 512 / 256 | **0.000125 元**（Batch 0.000063） | 100 万 token / 90 天 |
| qwen3.7-text-embedding | 2560 / 2048 / 1536 / 1024 / 768 / 512 / 256 | 0.0005 元 | 100 万 token / 90 天 |
| text-embedding-v4 | 2048 / 1536 / 1024 / 768 / 512 / 256 / 128 / 64 | 0.0005 元 | 100 万 token / 90 天 |
| text-embedding-v3 | 1024 / 768 / 512 / 256 / 128 / 64 | 0.0005 元 | 50 万 token |

**选 flash 的理由**：检索场景下它的性能/成本比最好，且同样是 **1024 维默认**（与 bge-m3 一致，方便将来对照评测）。

### 3.2 成本测算（按你的量级）

| 项 | 用量 | 费用 |
| --- | --- | --- |
| 建索引（一次性） | 5000 段 × 500 token = 250 万 token | **≈ 0.31 元**（一次性） |
| 在线检索 | 1000 次/天 × 50 token = 150 万 token/月 | **≈ 0.19 元/月** |

**Embedding 成本基本可忽略**，且 100 万免费额度足够覆盖建索引。不要为省这点钱把架构搞复杂。

### 3.3 接入方式（零新依赖）

百炼提供 OpenAI 兼容接口，直接用**已装好的 `langchain-openai`**：

```ini
# .env 新增
EMBEDDING_PROVIDER=dashscope
EMBEDDING_BASE_URL=https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
EMBEDDING_API_KEY=sk-xxx            # 百炼控制台获取，与 DeepSeek 的 key 不同
EMBEDDING_MODEL=qwen3.7-text-embedding-flash
EMBEDDING_DIM=1024
VECTOR_STORE=numpy                  # 语料 <1 万段时不需要向量库
```

```python
# app/store/embedding.py（P2 新增）
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(
    model="qwen3.7-text-embedding-flash",
    base_url=settings.embedding_base_url,
    api_key=settings.embedding_api_key,
    dimensions=1024,
    check_embedding_ctx_length=False,   # 避免 tiktoken 对国产模型的误判
)
```

> ⚠️ **两个待实测确认项**（开工时验证，不要凭猜）：
> 1. **`{WorkspaceId}`** —— 新的业务空间 ID 占位符，从百炼控制台获取。若控制台给的是传统地址
>    `https://dashscope.aliyuncs.com/compatible-mode/v1`，用传统地址即可，以控制台实际值为准。
> 2. **`text_type`（`query` / `document`）** —— 通义 embedding 的特色参数，入库文档用 `document`、
>    检索查询用 `query`，能提升召回。但**它可能不被 OpenAI 兼容接口支持**。
>    若不支持，起步先不用（差异不大），后续需要高级特性再改用 DashScope SDK。

### 3.4 向量库：先不要引入

| 语料量级 | 方案 |
| --- | --- |
| **< 1 万段** | 向量存 numpy 数组，暴力算余弦相似度。5000×1024 ≈ 20MB，单次查询 ~5ms |
| > 1 万段 | 再上 Chroma / Milvus / pgvector（阿里云可选 **RDS PostgreSQL + pgvector** 或 **Lindorm 向量引擎**） |

> 结论：P2 起步用 `VECTOR_STORE=numpy`，**零新依赖**。等语料真的上万段再换。

### 3.5 关于"供应商绑定"

之前我强调过"选开源模型（bge-m3）能保住供应商可替换性"。**在你的场景下这条建议的权重下降了**，因为：

- 你的语料只有几千段，**重建索引只是一次脚本运行**（几分钟 + 不到 1 元）
- 百炼和你的 ECS 同地域，网络延迟低、账单统一、无需额外供应商

所以选百炼是合理的。**唯一要记住的约束是**：向量维度和模型绑定，将来换 embedding 模型必须重建索引——把建索引脚本写成一键可重跑，这个问题就消失了。

## 4. 部署拓扑（推荐）

```
┌──────────────────────── 一台 ECS（北京地域） ────────────────────────┐
│                                                                      │
│   ┌────────────────┐        ┌──────────────────────────────┐        │
│   │  主服务 (Go)    │ HTTP   │  AI 派蒙服务 (Python)         │        │
│   │  容器 :8080     │───────►│  容器 :8090                   │        │
│   │  对外: 安全组    │        │  仅 127.0.0.1:8090（不对公网） │        │
│   └───────┬────────┘        └───────────────┬──────────────┘        │
│           │                                  │                       │
│           ▼                                  ▼                       │
│      MySQL (RDS 或本机)              api.deepseek.com（公网 443）      │
│                                     百炼 Embedding（公网 443，P2）     │
│                                                                      │
│   日志：容器 stdout → SLS                                              │
└──────────────────────────────────────────────────────────────────────┘
```

**为什么推荐同机**：

| | 同机 | 跨机 |
| --- | --- | --- |
| 网络 | `127.0.0.1`，天然不暴露 | 需内网 IP + 安全组规则 |
| 成本 | 省一台 ECS | 多一台 |
| 单点故障 | 一起挂 | 可隔离 |

对当前规模，**同机的收益远大于代价**。等主服务需要独立扩容时再拆。

## 5. 实施步骤

### 步骤 1：准备 ECS

```
镜像：Alibaba Cloud Linux 3 / Ubuntu 22.04
规格：2 vCPU / 4 GiB（AI 服务 + 主服务共用，建议不低于 4 GiB）
系统盘：40 GiB ESSD
公网：分配公网 IPv4，带宽按量或 1~5 Mbps 固定
安全组：见 §2.2
```

**验证**：

```bash
uname -a && free -m && df -h /
# 预期：内存 available ≥ 2GiB、磁盘余量 ≥ 20GiB

curl -sI https://api.deepseek.com | head -1
# 预期：HTTP/2 401 或 403（能连通即说明出网正常；401 是因为没带 key）
```

> 若上面 curl 超时 → 出网没配好，回到 §2.1。**这一步不通，后面全白做。**

### 步骤 2：安装 Docker + 配镜像加速

```bash
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker

# 阿里云容器镜像服务提供的加速器（在 ACR 控制台获取专属地址）
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'JSON'
{
  "registry-mirrors": ["https://<你的ACR加速器地址>.mirror.aliyuncs.com"],
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
JSON
systemctl restart docker
docker info | grep -A2 'Registry Mirrors'
```

### 步骤 3：上传代码并配置

```bash
mkdir -p /opt/teyvat-ai && cd /opt/teyvat-ai
# 上传代码（排除 .env）
cp .env.example .env
# 编辑 .env：AI_SERVICE_KEY / DEEPSEEK_API_KEY / （P2 时）EMBEDDING_*
chmod 600 .env
```

**验证**：`grep -c '^AI_SERVICE_KEY=$' .env` → 预期 `0`

### 步骤 4：构建启动（或从 ACR 拉镜像）

```bash
# 方式一：ECS 上直接构建
docker compose up -d --build

# 方式二：本地/CI 构建后推 ACR，ECS 只拉取（推荐，省 ECS 资源）
#   本地： docker build -t <ACR地址>/teyvat-ai:0.1.0 .
#          docker push <ACR地址>/teyvat-ai:0.1.0
#   ECS：  docker login <ACR地址> && docker compose up -d

docker compose ps      # 等 (healthy)
```

### 步骤 5：跑 04 文档的 12 项验收清单

```bash
curl -s http://127.0.0.1:8090/health
# 预期 {"code":0,...,"status":"up"}

# 外网不可达验证（从你的办公机执行）
curl -m 5 http://<ECS公网IP>:8090/health    # 预期：超时/拒绝
```

## 6. 时区注意

阿里云 ECS 默认可能是 **UTC**。我们的日志时间戳是 ISO-8601 的 UTC（`ts=2026-09-11T...Z`），**这是对的，不要改**。但和北京时间差 8 小时，排查时注意换算；若需统一可改系统时区（不影响服务逻辑）。

## 7. 日志与监控（SLS + 云监控）

### 7.1 采集到 SLS

服务日志已是**每行一个 JSON**、字段对齐 zap（`level` / `ts` / `msg`），SLS 可以直接结构化解析：

```
SLS 采集配置：
  数据源：Docker 容器 stdout（Logtail 容器模式，或 json-file + 主机路径采集）
  解析模式：JSON
  关键字段：level, ts, msg, code, tokens_cached, tokens_total, elapsed_ms
```

### 7.2 建议告警规则（可直接配）

| 告警 | 条件 | 级别 |
| --- | --- | --- |
| 服务不可用 | `/health` 连续 3 次非 200（云监控站点监控） | 紧急 |
| 提示词来源故障 | 出现 `persona.prompts_unavailable_using_fallback` | 紧急 |
| 内部接口故障 | 出现 `prompt_store.http_failed` | 紧急 |
| 上游异常 | `code=502/503/504` 的 `request.failed` 占比 > 5% | 警告 |
| 缓存失效 | `tokens_cached` 长期为 0 | 提示（说明有人往提示词里塞了动态内容） |
| 成本异常 | `tokens_total` 日增幅突增 | 警告（防刷量） |

> `llm.temperature_ignored_in_thinking_mode` 属正常提示，**不要告警**。

## 8. 密钥管理

| 阶段 | 做法 |
| --- | --- |
| **起步** | `.env` + `chmod 600` + `.gitignore`（现状即可） |
| 进阶 | **KMS 凭据管家**：密钥存凭据管家，容器启动时通过 RAM 角色拉取，`.env` 里不再有明文 |
| 更稳 | ECS 绑定 RAM 角色 → 免 AK 访问云服务（避免在服务器上放 AccessKey） |

**要注意的密钥共 4 类**：

| 变量 | 来源 | 用途 |
| --- | --- | --- |
| `AI_SERVICE_KEY` | 自己生成 | 主服务调用本服务的凭证 |
| `DEEPSEEK_API_KEY` | DeepSeek 平台 | 对话模型 |
| `EMBEDDING_API_KEY` | 百炼控制台 | 向量化（P2） |
| `PROMPT_STORE_KEY` | 与主服务约定 | 内部接口（切 `http` 模式时） |

## 9. 成本估算（量级参考）

| 项 | 量级 | 说明 |
| --- | --- | --- |
| ECS 2vCPU/4GiB | 数十~百余元/月 | 包年更省；与主服务共用一台 |
| 公网带宽 | 数十元/月 | 1~5 Mbps 固定带宽，仅用于出网调用 API |
| ACR 个人版 | **免费** | — |
| SLS | 个位数元/月 | 日志量很小 |
| DeepSeek 对话 | 按量 | **成本大头**；实测单次 chat input ≈ 600 tokens，其中约 380 命中缓存 |
| 百炼 Embedding | **< 1 元/月** | §3.2 已算 |
| ~~NAT 网关~~ | **避免** | 单机场景数百元/月，不划算 |

**优化点**：DeepSeek 的**缓存命中价差 50 倍**，所以「人格提示词稳定在前」的设计是持续省钱的关键——不要往提示词里塞时间戳或随机值。

## 10. 阿里云特有的坑（清单）

| # | 坑 | 表现 | 处理 |
| --- | --- | --- | --- |
| 1 | **ECS 无公网出口** | `/v1/complete` 返回 502/504，但 `/health` 正常 | 配公网带宽/NAT/EIP；先 `curl -sI https://api.deepseek.com` 验证 |
| 2 | **出方向收紧后云服务失联** | 云助手、云监控 Agent 异常 | 放行 `100.100.0.0/16` 的 80/443 |
| 3 | **安全组无法按域名限制出方向** | 想只放行 DeepSeek 却做不到 | 单机保持出方向默认允许，靠密钥防护 |
| 4 | 默认入方向含 `0.0.0.0/0:22` | SSH 被爆破 | 改成你的固定 IP/32 |
| 5 | 误把 8090 映射到公网 | 接口可被任意调用 | compose 里必须是 `127.0.0.1:8090:8090`，且安全组不放行 8090 |
| 6 | 时区为 UTC | 日志时间和北京时间差 8h | 排查时换算；日志本身不用改 |
| 7 | 拉取 Docker Hub 镜像慢 | `docker compose up --build` 卡住 | 配 ACR 镜像加速器（§5 步骤 2） |
| 8 | pip 拉包慢/失败 | 构建报网络错误 | Dockerfile 构建时用阿里云 PyPI 镜像源 |
| 9 | 内存不足 | 容器反复重启 | AI 服务含 langchain 依赖，建议可用内存 ≥ 1GiB；`docker stats` 观察 |
| 10 | 百炼 `base_url` 含 `{WorkspaceId}` | 401/404 | 以百炼控制台实际给的地址为准，不要照抄文档占位符 |
