# 04 · 部署与运维接入说明（AI 执行版）

> **读者**：负责把 `teyvat-ai`（AI 派蒙服务）接入运维服务器的 AI 代理或运维工程师。
> **目标**：在目标服务器上把服务跑起来、接上主服务、通过全部验收项，并留下可运维的状态。
> **前置阅读**：`01-接口契约.md`（对外契约，必读）、`02-AI派蒙架构设计-DeepSeek方案.md`（架构）、`03-主服务对接说明.md`（主服务侧改动）。

---

## 0. 给执行者（AI）的硬性要求

1. **先问、再动**：§1 表格里标【必问】的项，没有答案就停下来问用户，**禁止猜测**。标【默认】的项可以按默认值执行，但要告知用户你用了默认值。
2. **每步都验证**：§4 / §5 每个步骤末尾都有「验证」，输出与预期不符就停下排查，不要往下走。
3. **不要做的事**：
   - ❌ 不要把 `AI_SERVICE_KEY` 或 `DEEPSEEK_API_KEY` 写进任何提交到 Git 的文件（只能写进服务器上的 `.env`）
   - ❌ 不要把 8090 端口暴露到公网
   - ❌ 不要用 `AI_RELOAD=1`（热重载）跑生产
   - ❌ 不要改 `pyproject.toml` 里的依赖版本去"修"安装问题，先报告
4. **遇到与本文档不一致的事实**（比如系统没装 systemd、端口被占用），**以实际环境为准并把偏差记录到 §12 交接表**，不要强行套用。
5. 全部完成后，把 §12 交接确认表填好交付给用户。

| 依赖 | 用途 | 不可用时的后果 |
| --- | --- | --- |

## 2. 架构与网络拓扑

```
┌──────────────────────┐        HTTP (X-AI-Key)        ┌────────────────────────┐
│  主服务 teyvat-guide  │ ────────────────────────────► │  AI 派蒙服务 teyvat-ai  │
│  :8080               │ ◄──── 仅被调用，不主动回调 ──── │  :8090（不对外暴露）     │
└──────────────────────┘                               └───────────┬────────────┘
                                                                   │ HTTPS
                                                                   ▼
                                                        DeepSeek API (公网)
```

### 2.1 端口矩阵

| 端口 | 服务 | 暴露范围 |
| --- | --- | --- |
| 8090 | AI 派蒙服务 | **仅内网/回环**，禁止公网 |
| 8080 | 主服务 | 按主服务既有策略 |
| 3306 | MySQL | 内网，AI 服务**不连接** |
| 5173 | 前端开发服务 | 仅开发 |

### 2.2 出网要求

服务器需要能访问 `https://api.deepseek.com`（HTTPS/443）。若走代理，需在 systemd/compose 里配置 `HTTPS_PROXY`。

## 4. 方案 A：Docker 部署（推荐）

### 4.0 前置检查（验证）

```bash
docker --version && docker compose version
# 预期：Docker 24+ / Compose v2（输出形如 Docker version 2x.x.x、Docker Compose version v2.x.x）
```

> 若未安装 Docker：`curl -fsSL https://get.docker.com | sh`
> 若服务器在中国大陆且拉取镜像慢，配置镜像加速器后再继续。

### 4.1 上传代码

```bash
mkdir -p /opt/teyvat-ai && cd /opt/teyvat-ai
# 上传/克隆到此处，确认存在：app/ prompts/ pyproject.toml Dockerfile docker-compose.yml
ls -1
```

**验证**：`ls` 输出中包含 `Dockerfile`、`docker-compose.yml`、`pyproject.toml`、`app`、`prompts`。

### 4.2 生成 `.env`

```bash
cd /opt/teyvat-ai
cp .env.example .env

# 生成服务密钥并填入（若用户未提供）
python3 -c "import secrets;print('AI_SERVICE_KEY='+secrets.token_urlsafe(32))"

# 编辑 .env，至少确认以下项：
```

`.env` 必填项：

```ini
AI_SERVER_HOST=0.0.0.0          # 容器内必须 0.0.0.0（compose 已覆盖，此处保持一致）
AI_SERVER_PORT=8090
AI_SERVICE_KEY=<生成的或用户提供的值>
DEEPSEEK_API_KEY=<用户提供>
DEEPSEEK_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-flash
PROMPT_STORE_MODE=file          # 或 http（此时还要填 PROMPT_STORE_URL / PROMPT_STORE_KEY）
```

```bash
chmod 600 .env          # 密钥文件收紧权限
```

**验证**：

```bash
grep -c '^AI_SERVICE_KEY=$' .env    # 预期 0（即已填值）
grep -c '^DEEPSEEK_API_KEY=$' .env  # 预期 0
```

### 4.3 构建并启动

```bash
docker compose up -d --build
docker compose ps
```

**验证**：`docker compose ps` 的 `STATUS` 在约 20 秒后变为 `Up ... (healthy)`。

### 4.4 联调验证

```bash
# 1) 健康检查（无需鉴权）
curl -s http://127.0.0.1:8090/health
# 预期：{"code":0,"message":"ok","data":{"status":"up","version":"0.1.0","extras":{...}}}

# 2) 无鉴权必须被拒
curl -s -o /dev/null -w '%{http_code}\n' -X POST http://127.0.0.1:8090/v1/complete \
  -H 'Content-Type: application/json' -d '{"prompt":"hi"}'
# 预期：401

# 3) 真实补全（会消耗 DeepSeek 额度）
KEY=$(grep '^AI_SERVICE_KEY=' .env | cut -d= -f2)
curl -s -X POST http://127.0.0.1:8090/v1/complete \
  -H 'Content-Type: application/json' -H "X-AI-Key: $KEY" \
  --data-binary @- <<'JSON'
{"prompt":"用一句话介绍你自己","options":{"profile":"chat"}}
JSON
# 预期：{"code":0,...,"data":{"reply":"...派蒙...","model":"deepseek-flash","tokens":{...}}}
```

**验证**：三项输出与预期一致。若第 3 项返回 `502 上游模型鉴权失败`，说明 `DEEPSEEK_API_KEY` 填错。
若返回 `504/503`，检查服务器能否访问 `api.deepseek.com`。

### 4.5 确认未暴露公网

```bash
# 从另一台外网机器执行（不要在本机执行）
curl -m 5 http://<公网IP>:8090/health
# 预期：超时或 connection refused
```

若意外可通，立即检查：`docker compose ps` 的 PORTS 列必须是 `127.0.0.1:8090->8090/tcp`，以及防火墙规则。

## 5. 方案 B：裸机 systemd 部署（Linux）

### 5.1 安装依赖

```bash
# Debian/Ubuntu
apt update && apt install -y python3 python3-venv python3-pip
python3 --version        # 预期：>= 3.11

# RHEL/CentOS/Rocky
# dnf install -y python3.11 python3.11-pip
```

**验证**：`python3 -V` 输出 `Python 3.11` 或更高。低于 3.11 时**停下**告知用户（代码要求 `>=3.11`）。

### 5.2 创建用户与目录

```bash
useradd --system --create-home --home-dir /opt/teyvat-ai --shell /usr/sbin/nologin teyvat-ai
mkdir -p /opt/teyvat-ai /var/log/teyvat-ai
# 上传代码到 /opt/teyvat-ai（注意排除 .env）
chown -R teyvat-ai:teyvat-ai /opt/teyvat-ai /var/log/teyvat-ai
```

### 5.3 安装依赖

```bash
cd /opt/teyvat-ai
sudo -u teyvat-ai python3 -m venv .venv
sudo -u teyvat-ai ./.venv/bin/python -m pip install --upgrade pip
sudo -u teyvat-ai ./.venv/bin/python -m pip install .
# P2/P3 需要时： pip install ".[rag]" 或 ".[rag,graph]"
```

**验证**：

```bash
sudo -u teyvat-ai ./.venv/bin/python -c "import app, fastapi, langchain_openai; print('deps ok', app.__version__)"
# 预期：deps ok 0.1.0
```

### 5.4 生成 `.env`

同 §4.2（但 `AI_SERVER_HOST` 按 §1 第 6 项决定）：

```bash
cd /opt/teyvat-ai
cp .env.example .env
# 编辑 .env 填入 AI_SERVICE_KEY / DEEPSEEK_API_KEY
chmod 600 .env && chown teyvat-ai:teyvat-ai .env
```

> 键值含特殊字符时用引号包住；`.env` 由 Python 读取（UTF-8），**不要**依赖 shell 的 `source` 来加载。

### 5.5 systemd 单元

`/etc/systemd/system/teyvat-ai.service`：

```ini
[Unit]
Description=teyvat-ai (AI Paimon service)
Documentation=file:/opt/teyvat-ai/README.md
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=teyvat-ai
Group=teyvat-ai

# 关键：工作目录必须是应用根目录，应用通过相对路径读取 .env 与 prompts/
WorkingDirectory=/opt/teyvat-ai

Environment=PYTHONUNBUFFERED=1
Environment=PYTHONDONTWRITEBYTECODE=1
# 只从 .env 读配置（应用自己会读），避免 systemd EnvironmentFile 与 .env 形成双份真相
# 如需在外部覆盖个别变量，再启用下面这行：
# EnvironmentFile=/opt/teyvat-ai/.env

ExecStart=/opt/teyvat-ai/.venv/bin/python -m app.main

Restart=always
RestartSec=3
TimeoutStopSec=20

# 安全加固
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/log/teyvat-ai
ProtectKernelTunables=true
ProtectControlGroups=true
RestrictSUIDSGID=true

StandardOutput=append:/var/log/teyvat-ai/service.log
StandardError=append:/var/log/teyvat-ai/service.log

[Install]
WantedBy=multi-user.target
```

> **兼容性提示（执行前先确认，避免卡住）**：
> - `StandardOutput=append:` 需要 **systemd ≥ 240**（`systemd --version` 查看）。低于该版本会报
>   `Failed to parse output specifier`，此时删掉这两行，改用 `journalctl -u teyvat-ai` 看日志。
> - `/usr/sbin/nologin` 在部分发行版位于 `/sbin/nologin`；`useradd` 报错时换成实际路径，或省略 `--shell`。
> - `ProtectSystem=strict` 会把除 `ReadWritePaths` 之外的路径挂成只读。应用本身不写盘
>   （已设 `PYTHONDONTWRITEBYTECODE=1`），所以不需要给代码目录写权限。
> - 若应用需要走 HTTP 代理访问 DeepSeek，在 `[Service]` 中追加 `Environment=HTTPS_PROXY=http://...`。

```bash
systemctl daemon-reload
systemctl enable --now teyvat-ai
systemctl status teyvat-ai --no-pager
```

**验证**：

```bash
systemctl is-active teyvat-ai     # 预期：active
journalctl -u teyvat-ai -n 30 --no-pager
# 预期日志中出现：
#   [info] prompt_store.backend  mode=file path=prompts/paimon.json
#   [info] service.started  host=... port=8090 model=deepseek-flash ...
```

若状态为 `failed`，看日志中是否有：

```
RuntimeError: 配置校验未通过：
  - AI_SERVICE_KEY 为空。...
  - DEEPSEEK_API_KEY 为空，无法调用上游模型。
```

→ 说明 `.env` 没填好；填好后 `systemctl restart teyvat-ai`。

> 这个「启动即失败并明确列出缺什么」是**刻意设计**，不要为了让它起来而设置 `ALLOW_INSECURE_DEV=true`（那会关闭鉴权，等于把 `/v1/*` 裸奔）。

### 5.6 联调验证

同 §4.4（把 `127.0.0.1:8090` 换成实际绑定地址）。

### 5.7 日志轮转

`/etc/logrotate.d/teyvat-ai`：

```

    daily
    rotate 14
    compress
    delaycompress
```

### 6.1 无状态验证（可选但推荐）

```bash
# 连发两次相同请求，确认语料前缀缓存生效、且服务不持有会话状态
```

### 6.2 性能基线

| 指标 | 参考值（实测） |
| --- | --- |
| `/health` 响应 | < 50ms |
| `chat` 档首字（非流式整体） | ≈ 0.9 ~ 1.3s |
| `analysis` 档（思考模式） | 明显更慢，可到 10s+，属正常 |
| 单次 chat 用量 | input ≈ 600 tokens（含人格前缀），其中约 380 命中缓存 |

### 6.3 反向代理（若有）

`/v1/complete/stream` 是 SSE，Nginx 必须关闭缓冲，否则前端收不到逐字输出：

```nginx
location /v1/ {
    proxy_pass http://127.0.0.1:8090;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;          # 关键
    proxy_read_timeout 120s;
}
```

### 8.3 建议的告警项

| 指标 | 阈值建议 |
| --- | --- |
| `/health` 非 200 | 连续 3 次 → 告警 |
| 日志 `request.failed` 中 `code=502/503/504` 占比 | > 5% → 告警（上游或额度问题） |
| 日志 `persona.prompts_unavailable_using_fallback` 出现 | 立即告警（提示词来源故障） |
| 日志 `prompt_store.http_failed` | 立即告警（主服务内部接口故障） |
| `tokens_cached` 长期为 0 | 提示前缀缓存失效（通常意味着有人往提示词里塞了动态内容） |
| 日志 `llm.temperature_ignored_in_thinking_mode` | 属正常提示，无需告警 |

## 9. 故障排查表

| 现象 | 可能原因 | 排查 / 处理 |
| --- | --- | --- |
| 启动失败，日志列出「AI_SERVICE_KEY 为空」 | `.env` 未填或工作目录不对 | 确认 `WorkingDirectory=/opt/teyvat-ai` 且 `.env` 在同一目录 |
| 启动失败，「DEEPSEEK_API_KEY 为空」 | 同上 | 填好后重启 |
| `/v1/complete` 返回 `401 缺少 X-AI-Key` | 调用方没带 header 或值为空 | 确认主服务 `TEYVAT_AI_API_KEY` 与 AI 服务 `AI_SERVICE_KEY` **完全一致** |
| `/v1/complete` 返回 `502 上游模型鉴权失败` | DeepSeek key 错/过期 | 重新生成 key |
| `/v1/complete` 返回 `503 上游模型限流` | 并发超限 | 调低 `LLM_MAX_CONCURRENCY`（默认 32）；DeepSeek Flash 并发上限 2500 |
| `/v1/complete` 返回 `504 上游模型响应超时` | 网络到 DeepSeek 慢，或 `analysis` 档耗时过长 | 检查出网；`LLM_TIMEOUT_SECONDS` 默认 55，不建议调大（主服务 65s 兜底） |
| `400 参数不合法` | 请求体字段名/长度不合契约 | 对照 `01-接口契约.md` |
| 中文返回乱码 | 只在 PowerShell 客户端显示时出现 | 属**控制台编码**问题，非服务问题；`chcp 65001` |
| 端口被占用 | 已有进程监听 8090 | `ss -lntp \| grep 8090`；改 `AI_SERVER_PORT` |
| 503 / 服务起不来但日志无错 | 内存不足（首次加载 langchain 依赖较重） | `free -m`；建议 ≥ 512MB 可用内存 |
| 提示词没生效 | `PROMPT_STORE_MODE=file` 时改的是 DB、或 TTL 未过期 | 检查 `prompts/paimon.json`；缓存 TTL 默认 60s |
| Docker 构建失败 | 服务器无法访问 PyPI | 配 pip 镜像源或 `docker build --build-arg` 指定源 |

## 10. 安全基线（逐条确认）

- [ ] 8090 **不对公网开放**（外网实测不可达）
- [ ] `.env` 权限 `600`、属主为服务用户
- [ ] 仓库/压缩包内**无任何真实密钥**（`grep -rn "sk-" --exclude=.env` 无输出）
- [ ] 服务以**非 root** 用户运行
- [ ] `ALLOW_INSECURE_DEV=false`
- [ ] 未启用 `AI_RELOAD`（生产禁用热重载）
- [ ] AI 服务**不连接**业务数据库（无 MySQL 配置项）
- [ ] 上游原始错误不外泄（502/503/504 只返回归一化文案）
- [ ] 出网只放行 `api.deepseek.com:443`（若安全策略要求白名单）
