## 2. `service/ai.go`：新增 `remoteAIClient`

```go
package service

import (
	"bytes"
	"context"
	"encoding/json"
	"fmt"
	"net/http"
	"time"

	"teyvat-guide/server/pkg/logger"
)

// 与 AI 服务约定的信封
type aiEnvelope struct {
	Code    int             `json:"code"`
	Message string          `json:"message"`
	Data    json.RawMessage `json:"data"`
}

type aiCompleteData struct {
	Reply string `json:"reply"`
	Model string `json:"model"`
	Tokens struct {
		Input  int `json:"input"`
		Output int `json:"output"`
		Total  int `json:"total"`
		Cached int `json:"cached"`
	} `json:"tokens"`
	FinishReason string `json:"finishReason"`
	ElapsedMs    int    `json:"elapsedMs"`
}

type remoteAIClient struct {
	baseURL string
	apiKey  string
	model   string
	http    *http.Client
}

func NewRemoteAIClient(baseURL, apiKey, model string, timeout time.Duration) AIClient {
	return &remoteAIClient{
		baseURL: baseURL,
		apiKey:  apiKey,
		model:   model,
		http:    &http.Client{Timeout: timeout},
	}
}

func (c *remoteAIClient) Complete(
	ctx context.Context, system string, history []Message, prompt string,
) (string, int, error) {
	body := map[string]any{
		"system":  system,
		"history": history,
		"prompt":  prompt,
		"options": map[string]any{"model": c.model},
	}
	raw, err := json.Marshal(body)
	if err != nil {
		return "", 0, fmt.Errorf("marshal ai request: %w", err)
	}

	req, err := http.NewRequestWithContext(
		ctx, http.MethodPost, c.baseURL+"/v1/complete", bytes.NewReader(raw),
	)
	if err != nil {
		return "", 0, fmt.Errorf("build ai request: %w", err)
	}
	req.Header.Set("Content-Type", "application/json")
	req.Header.Set("X-AI-Key", c.apiKey)

	resp, err := c.http.Do(req)
	if err != nil {
		return "", 0, fmt.Errorf("call ai service: %w", err)
	}
	defer func() { _ = resp.Body.Close() }() // 显式忽略，见下方说明

	var env aiEnvelope
	if err := json.NewDecoder(resp.Body).Decode(&env); err != nil {
		return "", 0, fmt.Errorf("decode ai response (status=%d): %w", resp.StatusCode, err)
	}
	if env.Code != 0 {
		return "", 0, fmt.Errorf("ai service error: code=%d message=%s", env.Code, env.Message)
	}

	var data aiCompleteData
	if err := json.Unmarshal(env.Data, &data); err != nil {
		return "", 0, fmt.Errorf("decode ai data: %w", err)
	}
	return data.Reply, data.Tokens.Total, nil
}
```

`NewAIClient` 增加分支：

```go
func NewAIClient(cfg *config.AIConfig) AIClient {
	switch cfg.Provider {
	case "remote":
		return NewRemoteAIClient(
			cfg.BaseURL, cfg.APIKey, cfg.Model,
			time.Duration(cfg.TimeoutSeconds)*time.Second,
		)
	case "openai":
		return newOpenAIClient(cfg)
	default:
		return &mockClient{}
	}
}
```

> `defer func(){ _ = resp.Body.Close() }()` 是 `Close()` 无有意义的错误可处理，
> 属于规范允许的例外；业务错误一律不得用 `_ =` 吞掉。

现状：system 提示词在 `config.yaml` 的 `ai.system`。

新方案：**人格提示词归 AI 服务**（从 `ai_prompts` 表读），主服务的 `ai.system` 降级为"本次请求的补充指令"，

## 6. 让派蒙知晓用户绑定的 UID 角色（P1，模式 A）

### 6.1 数据链路

```
用户消息 → ChatService.Ask
   ├─ 1. 取用户绑定的 UID
   ├─ 2. 取玩家档案（Enka）—— 必须带缓存
   ├─ 3. 筛选 + 压缩 → context.player
   └─ 4. POST AI 服务 /v1/complete（带上 context）
                 ↓
        AI 服务：渲染成自然语言 → 拼到 system 尾部（动态区）
                 ↓
        稳定前缀（派蒙人格）继续命中缓存，只有档案部分未命中
```

**AI 服务侧已经就绪**（`context.player` 契约 + 渲染 + 预算裁剪），主服务只需组装并传过去。
AI 服务不落库、不查询，用户数据只存在于该次请求的内存中。

### 6.2 步骤 1：取档案（必须缓存 + 可降级）

```go
type PlayerProfileProvider interface {
    GetByUID(ctx context.Context, uid string) (*PlayerProfile, error)
}
```

实现要点：

- Enka 是第三方接口，**慢且有限流** → 按 UID 缓存，建议 TTL 5~10 分钟；
- 并发同一 UID 时做单飞（singleflight），避免缓存击穿打爆 Enka；
- 拿不到就返回错误，由调用方降级 —— **不要让它阻塞聊天**。

```go
// ChatService.Ask 内
var ctxPayload map[string]any
if uid, ok := s.userSvc.BoundUID(ctx, userID); ok {
    profile, err := s.profileProvider.GetByUID(ctx, uid)
    if err != nil {
        // 关键：拉档案失败不能让聊天失败，降级为「不带 context」的普通问答
        logger.L().Errorw("load player profile failed", "err", err, "uid", uid)
    } else {
        ctxPayload = buildAIContext(profile, req.Message)
    }
}
```

### 6.3 步骤 2：组装 context（分级注入控制 token）

```go
// buildAIContext 组装给 AI 服务的玩家上下文。
//
// 分级策略：所有角色给「概览」，只有与提问相关的角色才展开「明细」（圣遗物主词条）。
// 既做到"完全知晓"，又把 token 压在预算内。
func buildAIContext(p *PlayerProfile, question string) map[string]any {
    mentioned := matchCharacterNames(question, p.Characters) // 问题中点名的角色
    building := isBuildingIntent(question)                   // 是否养成类意图

    chars := make([]map[string]any, 0, len(p.Characters))
    for _, c := range p.Characters {
        item := map[string]any{
            "name":          c.Name,
            "level":         c.Level,
            "constellation": c.Constellation,
            "talents": map[string]int{
                "normal": c.TalentNormal,
                "skill":  c.TalentSkill,
                "burst":  c.TalentBurst,
            },
            "weapon": map[string]any{
                "name":   c.WeaponName,
                "refine": c.WeaponRefine,
                "level":  c.WeaponLevel,
            },
        }
        if mentioned[c.Name] || building {
            item["artifacts"] = toArtifactPayload(c.Artifacts) // 含 mainStats
        } else {
            item["artifacts"] = toArtifactSummary(c.Artifacts) // 只给套装名 + 件数
        }
        chars = append(chars, item)
    }

    return map[string]any{
        "goal": questionGoal(question),
        "player": map[string]any{
            "uid":        p.UID,
            "nickname":   p.Nickname,
            "level":      p.Level,
            "characters": chars,
        },
    }
}
```

`artifacts` 两种粒度对应 AI 服务契约里的同一个字段：

```go
// 明细（推荐用于相关角色）
[]map[string]any{{
    "set":   "炽烈的炎之魔女",
    "count": 4,
    "mainStats": map[string]string{
        "时之沙": "攻击力%", "空之杯": "火元素伤害加成", "理之冠": "暴击率",
    },
}}

// 概览
[]map[string]any{{"set": "炽烈的炎之魔女", "count": 4}}
```

### 6.4 步骤 3：透传给 AI 服务


### 6.5 三个硬约束

| 约束 | 原因 |
| --- | --- |
| 拉档案失败不能影响聊天 | 降级为不带 `context` 调用，派蒙照常回答 |
| Enka 数据必须缓存 + 单飞 | 第三方限流；每次对话都拉会拖慢首字延迟 |
| 用户数据不写进 AI 服务的库 | AI 服务无状态，数据只在请求内存中 |

### 6.6 关于"完全知晓"的 token 现实

| 粒度 | 每个角色约 | 30 个角色 |
| --- | --- | --- |
| 概览（名字/等级/命座/天赋/武器） | 25~30 tokens | ≈ 800 tokens |
| 明细（再含圣遗物主词条） | 60~80 tokens | ≈ 2000 tokens（会超预算） |

结论：**"完全知晓"落在概览层是可行的**（30 个角色约 800 tokens，在 1500 预算内）；
若全部展开圣遗物明细会超预算，AI 服务会**整条丢弃末尾角色**并在提示里注明
「其余 N 个角色已省略」——不会给出半个角色条目（半个条目比没有更容易误导模型）。

> 注：预算用的是近似 token 计数器，响应里的 `data.tokens` 才是 DeepSeek 返回的真实用量。
> 上线后按真实用量校准 `PLAYER_CONTEXT_BUDGET_TOKENS`。

### 6.7 前端展示用不到的字段怎么办

如果 Enka 返回的原始字段很多，**不要整段透传**。只挑契约里的字段发过去，
其余一律靠 `context.summary` 作为自由文本补充（AI 服务会把它放在档案之前）：

```go
ctxPayload["summary"] = "该玩家深境螺旋 12-3 未满星，主练火系队伍"
```
