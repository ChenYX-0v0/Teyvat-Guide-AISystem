# 01 · 接口契约

> **本文是 AI 派蒙服务对外 HTTP 契约的权威表述**（人类可读版）。
> 机器可校验的权威在代码：`app/schemas/chat.py`、`app/core/envelope.py`。两者冲突时**以代码为准**，并回来修本文。
> **读者**：主服务开发者、前端开发者、以及任何需要对接本服务的人。

---

## 1. 通用约定

| 项 | 约定 |
| --- | --- |
| 基地址 | `http://<host>:8090` |
| 编码 | 请求与响应体一律 UTF-8 |
| 请求头 | `Content-Type: application/json` |
| 鉴权 | `X-AI-Key: <AI_SERVICE_KEY>`；**除 `/health` 外所有接口必填** |
| 响应信封 | `{"code": int, "message": string, "data": object \| null}`，**`code === 0` 表示成功** |
| HTTP 状态码 | 失败时 **HTTP 状态码 == `code`**（便于网关/重试策略直接判定） |
| 未知请求字段 | **忽略**（不报错）。这样主服务可以先发新字段，不必等服务端先升级 |
| 时间单位 | `elapsedMs` 为整数毫秒 |
| 网络暴露 | 本服务**不应暴露公网**（见 `04-部署运维接入说明.md` §10） |

### 1.1 服务端职责边界（决定契约里为什么没有某些字段）

| 归主服务 | 归 AI 服务 |
| --- | --- |
| 用户认证、会话与消息持久化、`chat_*` 表 | 人格注入、上下文裁剪、模型调用、用量统计 |
| 组装业务上下文（玩家档案等）并推送 | 只读使用，**不落库** |
| 面向用户的降级文案 | 上游归一化错误（不泄漏原始错误） |

## 2. `GET /health`

健康检查。**无需鉴权**，供主服务探活与运维探针使用。

**响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "status": "up",
    "version": "0.1.0",
    "extras": {
      "model": "deepseek-flash",
      "defaultProfile": "chat",
      "promptStoreMode": "file"
    }
  }
}
```

**约定**

- `data.status` 为 `up` 表示进程存活；`extras` 是诊断信息，**可能随时新增字段**，调用方只按需取用。
- 该接口**不代表上游模型可用**（DeepSeek 挂了它仍返回 `up`）。要验上游请用 `/v1/complete`。

## 3. `POST /v1/complete`（补全）

### 3.1 请求头

| 头 | 必填 | 说明 |
| --- | --- | --- |
| `X-AI-Key` | ✅ | 与 AI 服务的 `AI_SERVICE_KEY` 完全一致 |
| `Content-Type` | ✅ | `application/json` |

### 3.2 请求体

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `system` | string \| null | — | ≤ 20000 字符 | **补充指令**，会拼在本服务人格提示词**之后**（动态区）。本服务的人格由服务端提供，不在此字段 |
| `history` | array | — | ≤ 40 条；全部 `content` 合计 ≤ 200000 字符 | 对话历史 |
| `history[].role` | `"user"` \| `"assistant"` | ✅ | **不允许 `system`** | 系统提示走顶层 `system` 字段 |
| `history[].content` | string | ✅ | ≤ 8000 字符 | 单条内容 |
| `prompt` | string | ✅ | 去首尾空白后非空；≤ 4000 字符 | 本次提问 |
| `context` | object | — | 见 §5 | 业务上下文的可选扩展 |
| `options` | object | — | 见 §3.3 | 生成参数 |

> 超限一律返回 `400`，不做静默截断（避免"以为发了其实没发"）。

### 3.3 `options`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `model` | string | — | 覆盖服务端默认模型。除非明确需要，**不要传** |
| `temperature` | number | 0 ~ 2 | ⚠️ **思考模式下无效**，服务端会丢弃并打日志；需要调语气请用 `profile: "chat"` |
| `maxTokens` | integer | 1 ~ 384000 | 不传则按档位默认 |
| `profile` | `"chat"` \| `"analysis"` \| `"tool"` \| `"json"` | — | 推理档位，见 §4。优先级最高 |
| `thinking` | boolean | — | 显式开关思考模式。**优先级低于 `profile`** |
| `reasoningEffort` | `"none"` \| `"low"` \| `"high"` \| `"max"` | — | 思考强度，配合 `thinking: true` 或 `analysis` 档 |

传未知的 `profile` 值会返回 `400`（枚举校验），所以**新增档位值需要双方同步升级**。

### 3.4 响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "reply": "旅行者！你终于来啦～",
    "model": "deepseek-flash",
    "tokens": {
      "input": 598,
      "output": 47,
      "total": 645,
      "cached": 384,
      "reasoning": 0
    },
    "finishReason": "stop",
    "elapsedMs": 1249,
    "profile": "chat",
    "thinking": false,
    "sources": null
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `reply` | 模型回复文本（已剔除思考过程，思考内容不回传） |
| `model` | **实际使用的**模型 ID |
| `tokens.input` / `output` / `total` | 真实用量，来自上游 |
| `tokens.cached` | **命中的前缀缓存 tokens**。单价约为未命中的 1/50，成本统计必须分开算 |
| `tokens.reasoning` | 思考模式产生的 tokens（**已计入 `output`**，不要重复累加） |
| `finishReason` | `stop` / `length`（被 maxTokens 截断）/ `content_filter` / `tool_calls` / `insufficient_system_resource` / `aborted` |
| `elapsedMs` | 服务端处理耗时（含上游调用） |
| `profile` / `thinking` | 服务端**实际生效**的档位与思考开关（可能与请求不同，因为服务端会按意图自动升档） |
| `sources` | **P2 预留**（RAG 引用来源），当前恒为 `null` |

### 3.5 完整示例

```json
{
  "system": "本次对话聚焦圣遗物词条，不要跑题",
  "history": [
    { "role": "user", "content": "胡桃怎么玩？" },
    { "role": "assistant", "content": "胡桃是火系主C，核心是元素战技期间的重击哦～" }
  ],
  "prompt": "那我的胡桃圣遗物怎么调？",
  "context": {
    "goal": "圣遗物调整",
    "player": {
      "uid": "100000001",
      "level": 58,
      "characters": [
        {
          "name": "胡桃",
          "level": 90,
          "constellation": 1,
          "talents": { "normal": 9, "skill": 9, "burst": 8 },
          "weapon": { "name": "护摩之杖", "refine": 1, "level": 90 },
          "artifacts": [
            { "set": "炽烈的炎之魔女", "count": 4,
              "mainStats": { "空之杯": "火元素伤害加成" } }
          ]
        }
      ]
    }
  },
  "options": { "profile": "analysis" }
}
```

## 4. 推理档位（`profile`）

上游只有**一个模型** `deepseek-flash`，"是否推理"由参数开关控制，因此本服务用**档位**而非多模型来表达。

| 档位 | 思考模式 | temperature | 默认 maxTokens | 适用场景 |
| --- | --- | --- | --- | --- |
| `chat` | 关闭 | 0.85 | 1024 | 日常闲聊、答疑（**只有关思考才能调语气**） |
| `analysis` | 开启（high） | — | 4096 | 养成数据分析、配队、词条收益 |
| `tool` | 关闭 | 0.2 | 2048 | 工具调用（思考模式不支持 `tool_choice=required`） |
| `json` | 关闭 | 0.1 | 2048 | 结构化输出 |

**不传 `options` 时服务端自动选档**：命中养成类意图（如「圣遗物怎么选」「还需要提升什么」）会自动升到 `analysis`，
否则用服务端默认档（`LLM_DEFAULT_PROFILE`，默认 `chat`）。

> 因此响应里的 `profile` 可能与请求不同——这是设计行为，不是 bug。

## 5. `context`（可选扩展字段）

用于主服务把**用户私有数据**推送给本服务（模式 A：Push）。**不传时行为与基础契约完全一致**，向后兼容。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `context.player` | object | 玩家档案；字段见下。**服务端不落库，只在该次请求内存中存在** |
| `context.player.uid` | string | 游戏 UID |
| `context.player.nickname` | string | 昵称 |
| `context.player.level` | integer | 冒险等阶 |
| `context.player.characters[]` | array | 角色列表（**禁止推送全图鉴**，见预算约束） |
| `context.player.characters[].name` | string | 角色名（必填） |
| `...level` / `...constellation` | integer | 等级 / 命座 |
| `...talents` | object | `{normal, skill, burst}` 整数 |
| `...weapon` | object | `{name, refine, level}` |
| `...artifacts[]` | array | `{set, count, mainStats:{槽位: 词条}}`；`mainStats` 可省略（只给套装概览） |
| `context.goal` | string | 本次目标场景，如「深境螺旋 12 层」 |
| `context.summary` | string | 主服务**预渲染的自由文本**摘要（结构化数据不适用时用它） |

**约束与行为**

| 项 | 说明 |
| --- | --- |
| 上下文预算 | 默认 1500 tokens。超预算时服务端**整条丢弃末尾角色**并注明「其余 N 个角色已省略」——**不会给出半个角色条目**（残缺数据比缺失更容易误导模型） |
| 粒度建议 | 全部角色给**概览**（等级/命座/天赋/武器）≈25~30 tokens/角色；仅对提问点名的角色展开圣遗物 `mainStats`。30 个角色概览约 800 tokens，在预算内 |
| 未知字段 | 忽略（可安全新增） |
| 缓存影响 | 该内容位于 system 尾部（动态区），**不影响**人格前缀的缓存命中 |

## 6. `POST /v1/complete/stream`（流式补全，SSE）

`Content-Type: text/event-stream`。**帧格式与 `data` 结构固定如下**，主服务据此透传给前端。

```
event: delta
data: {"text":"胡桃"}

event: delta
data: {"text":"是火元素"}

event: done
data: {"tokens":{"input":598,"output":47,"total":645,"cached":384,"reasoning":0},"finishReason":"stop","model":"deepseek-flash","elapsedMs":1840}

event: error
data: {"message":"上游模型响应超时"}
```

| 事件 | `data` 结构 | 说明 |
| --- | --- | --- |
| `delta` | `{"text": string}` | 增量文本，可多次 |
| `done` | `{"tokens": object, "finishReason": string, "model": string, "elapsedMs": int}` | **唯一终止成功事件** |
| `error` | `{"message": string}` | 已脱敏的错误文案；出现后连接即结束 |

**约定**

- ⚠️ **SSE 模式下没有外层信封**。因为 HTTP 200 在第一个字节时就已发出，后续错误只能通过 `error` 事件表达。
  主服务必须解析事件流，不能只看 HTTP 状态码。
- 事件序列必然是 `delta*` → (`done` | `error`)，不会出现 `done` 之后还有 `delta`。
- 客户端断连时服务端停止产出，不再消耗上游配额。
- 通过反向代理时**必须关闭响应缓冲**，否则会变成"攒完一次性吐出"：
  ```nginx
  proxy_buffering off;
  proxy_read_timeout 120s;
  ```
- 请求体与 `/v1/complete` **完全相同**（同一个 `CompleteRequest` 模型）。

## 7. 错误码

| `code` | 含义 | 主服务可重试 | 典型触发 |
| --- | --- | --- | --- |
| `400` | 入参不合法 | ❌ | 字段类型错、`prompt` 超 4000 字符、`history` 混入 `system`、未知 `profile` |
| `401` | `X-AI-Key` 缺失或错误 | ❌ | 密钥不一致（主服务 `TEYVAT_AI_API_KEY` ≠ AI 服务 `AI_SERVICE_KEY`） |
| `429` | 服务端限流 | ✅ 退避 | 预留（P4 实现） |
| `500` | AI 服务内部错误 | ✅ | 兜底；日志里有 `request.unhandled` |
| `502` | 上游模型错误 | ✅ | 含上游鉴权失败（`DEEPSEEK_API_KEY` 无效） |
| `503` | 上游限流 / 不可用 | ✅ | 上游 429/503、无法连接 |
| `504` | 上游超时 | ✅ | 超过 `LLM_TIMEOUT_SECONDS` |

**错误响应体**

```json
{ "code": 503, "message": "上游模型限流", "data": null }
```

> `message` 是**已归一化**的文案（见 `app/core/errors.py`）。上游原始错误、密钥、堆栈**永不外传**。

## 8. 超时、重试与降级

| 项 | 值 | 责任方 |
| --- | --- | --- |
| AI 服务上游超时 | 55s（`LLM_TIMEOUT_SECONDS`） | AI 服务 |
| AI 服务重试 | ≤ 1 次（`LLM_MAX_RETRIES`） | AI 服务 |
| 主服务调用超时 | 建议 65s（**必须 > 55s**） | 主服务 |
| 主服务重试 | ≤ 1 次（仅对 5xx / 超时） | 主服务 |
| 用户可见的降级文案 | 由主服务产出 | 主服务 |

**硬约束**：同步链路**禁止**"长超时 + 多次重试"叠加，否则会把连接和上游配额占满。
`4xx` **不要重试**（除了修参数重发）。

## 9. 兼容性承诺

| 变更类型 | 是否破坏性 | 说明 |
| --- | --- | --- |
| 响应新增字段 | ❌ 非破坏 | 调用方应忽略未知字段 |
| 请求新增**可选**字段 | ❌ 非破坏 | 服务端已忽略未知字段，双向兼容 |
| 放宽约束（如上限调大） | ❌ 非破坏 | — |
| 新增 `code` 值 | ❌ 非破坏 | 调用方按"非 0 即失败"处理即可 |
| **收紧约束**（如 `prompt` 上限 4000 → 1000） | ✅ **破坏** | 会导致原本正常的请求开始 400 |
| **改变字段含义**、删除字段、修改路径 | ✅ **破坏** | 需走版本化 |
| 修改信封结构 | ✅ **破坏** | — |
| 新增 `profile` 枚举值 | ⚠️ 半破坏 | 老客户端不传无影响；但客户端传未知值会被 400，需同步升级 |

**版本策略**：当前无 URL 版本号（`/v1/*` 即 v1）。破坏性变更另起 `/v2/*`，v1 保留过渡期。

## 11. 快速自检命令

```bash
KEY=<你的 AI_SERVICE_KEY>

# 1) 健康检查（无需鉴权）
curl -s http://127.0.0.1:8090/health

# 2) 无鉴权必须被拒（预期 HTTP 401）
curl -s -o /dev/null -w '%{http_code}\n' -X POST http://127.0.0.1:8090/v1/complete \
  -H 'Content-Type: application/json' -d '{"prompt":"hi"}'

# 3) 补全
curl -s -X POST http://127.0.0.1:8090/v1/complete \
  -H 'Content-Type: application/json' -H "X-AI-Key: $KEY" \
  -d '{"prompt":"你好呀派蒙","options":{"profile":"chat"}}'

# 4) 流式
curl -N -X POST http://127.0.0.1:8090/v1/complete/stream \
  -H 'Content-Type: application/json' -H "X-AI-Key: $KEY" \
  -d '{"prompt":"你好呀派蒙"}'
```

> Windows PowerShell 下请改用 `Invoke-RestMethod`，避免引号与编码问题（见 `../README.md` 的「联调验证」）。
